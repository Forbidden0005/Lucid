\# ExplainMyPC UI Guidelines



\# Design Goals



The interface should feel:



\* calm

\* intelligent

\* modern

\* trustworthy

\* readable

\* responsive



Users should feel:



> “My system is understandable.”



\---



\# Design Philosophy



Prioritize:



\* clarity

\* spacing

\* hierarchy

\* explainability



Avoid:



\* clutter

\* fear-based UX

\* dense tables everywhere

\* visual overload



\---



\# Visual Style



\## Inspiration



\* Windows 11 Fluent Design

\* modern telemetry dashboards

\* aerospace control systems

\* clean cybersecurity interfaces

\# Typography



\## Font



\* Segoe UI Variable



\## Sizing



\* Large headers: 28-36px

\* Section titles: 18-24px

\* Body text: 14-16px

\* Secondary text: 12-13px



Avoid tiny unreadable text.



\---



\# Layout Rules



\## Padding



\* Page margins: 32px

\* Card padding: 20-24px

\* Section spacing: 24-40px



\---



\# Card Design



Cards should:



\* use subtle elevation

\* have soft rounded corners

\* avoid hard borders

\* maintain breathing room



Cards are the core UI building block.



\---



\# Navigation



\## Sidebar



Primary navigation should remain:



\* stable

\* predictable

\* icon-supported

\* collapsible



Avoid deeply nested navigation.



\---



\# Dashboard Design



The dashboard should answer:



> “Is my PC okay?”



within seconds.



Prioritize:



\* health score

\* active issues

\* recommendations

\* telemetry visibility



\---



\# Explain My PC Design



This page is the flagship experience.



Outputs should:



\* feel conversational

\* explain causes

\* avoid jargon

\* prioritize actionable insights



GOOD:

“Several startup apps are slowing boot time.”



BAD:

“Boot threshold exceeded.”



\---



\# Animations



Use:



\* subtle fades

\* smooth transitions

\* telemetry line animations

\* soft scaling



Avoid:



\* excessive blur

\* bouncing effects

\* flashy RGB motion

\* distracting transitions



\---



\# Telemetry Visuals



Telemetry should:



\* feel smooth

\* feel alive

\* remain readable



Use:



\* line graphs

\* subtle glows

\* soft motion



Avoid:



\* excessive visual noise

\* overly bright graphs



\---



\# Risk Communication



Avoid:



\* manipulative warnings

\* exaggerated danger language



Prefer:



\* confidence indicators

\* severity levels

\* evidence-based explanations



\---



\# Accessibility



The UI must support:



\* keyboard navigation

\* screen readers

\* scalable text

\* high contrast readability

\* colorblind-friendly states



\---



\# Responsive Behavior



Support:



\* compact window layouts

\* ultrawide monitors

\* scaling at different DPI settings



\---



\# Empty States



Empty states should feel:



\* informative

\* calm

\* useful



Example:

“No major security issues detected.”



instead of:

“0 threats.”



\---



\# Loading States



Prefer:



\* skeleton loading

\* progressive rendering

\* incremental data updates



Avoid blocking screens.



\---



\# Trust Design Principles



The UI should ALWAYS explain:



\* why something was flagged

\* what caused it

\* what actions will do

\* whether rollback exists



Transparency builds trust.
